# メニュー編集: オプションの端の行の矢印で編集画面が落ちる

omochikaeri-docs#188

## 何が起きるか

オプションの最下行で「↓」、最上行で「↑」を押すと `menuInfo.itemOptionCheckbox` に穴が空く。
次の描画で `itemOptions`（`map((v) => v.split(","))`）が `undefined` に当たって投げ、編集画面が丸ごと消える。

守りが `<button>` ではなく内側の `<div>` に付いているので、端の行でも**中身の無いボタンが残る**。
見えないが tab 順には居るので Enter で押せる。

## 直す範囲

issue の「直し方」は2案あり、両方入れる。入口を塞ぐのと、規則そのものを守らせるのは別の話なので。

1. `v-if` を `<button>` 側へ移す — 押せないようにする
2. `positionUp` / `positionDown` の入れ替えを `src/utils/optionRows.ts` の純粋な関数に切り出し、端と範囲外を弾く — 別の入口から同じ間違いが入っても止まる

2 は `optionMovedUp` / `optionMovedDown` として `toOptionRows` などと同じ場所に置く。
並べ替えの規則が既にそこに集まっているため。

## 確かめ方

- 端から先へ動かそうとしたときに配列が変わらないこと、長さが変わらないこと、穴が空かないこと → `test/unit/test_optionRows.ts`
- 範囲内の入れ替えが**直す前と同じ結果**であること → 直す前の実装をそのまま写した台で、生成した入力を突き合わせる
- 端の行のボタンが DOM から消え、tab で届かなくなること／消しても行の見た目がずれないこと → 出荷する markup をそのまま抜き出して browser で測る

## やらないこと

ドラッグでの並べ替え（#179 で入れたもの）には触れない。あちらは `vuedraggable` が配列を作り直すので、この穴は空かない。
