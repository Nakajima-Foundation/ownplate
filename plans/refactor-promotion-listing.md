# 客に出す券の絞り込みと並びを Firebase から切り離して試験を足す

SingularitySociety/omochikaeri-docs#212 の続き（#1858 で金額まわりを扱った残り）。

## 何をしたか

`src/utils/promotion.ts` に残っていた純粋な規則5つを `src/utils/promotionRules.ts` へ。

- `compareForAdmin` — 管理画面の一覧の並び
- `compareForCustomer` — 客に出す一覧の並び
- `hasStarted` — 期間つきの券が始まっているか
- `splitPromotionIdsByLookup` — 使用履歴を文書 id で引くか、中の promotionId で引くか
- `usablePromotions` — **まだ使える券だけを残す**。客の画面に出る券を決める

composable の外枠（`onSnapshot`・`getDocs`・`watch`・`onUnmounted`）は触っていない。

### 一つだけ、削った行がある

管理画面の並び替えに `a.enable !== b.enable` の分岐が**二度**書かれていた。二度目は
一度目を抜けた時点で必ず偽なので到達しない。切り出しでは一度だけにしてある。
**削ってよいことは読んで決めていない** — 下の比較で、二度書かれた旧と一度の新を
突き合わせて確かめた。

### 時計を読む位置は変えていない

`hasStarted` に渡す `new Date()` は、いったん呼び出しの外へ出しかけたが戻した。
旧は要素ごとに取っていて、一括にすると境目をまたぐ券の扱いが変わりうる。

## 挙動が同じであることの確かめ方

**旧の式をそのまま写して、並べて走らせた。** 並び替えは比較関数の戻りではなく
**並んだ結果の配列ごと**比べている（観測できるのはそちらなので）。

要素数0〜6の無作為な一覧を規則ごとに数百通り、履歴の形（未設定・空・使用済み・未使用・
配列・`__proto__`・null・0・空文字）も振った。**違いは出なかった。**

直した行を一つずつ壊すと**12通りすべてで差が出て**、戻すとゼロに戻る。
足した試験も同じ変異で全部赤くなる。

## 前回の CI の落ち方を繰り返していないことも確かめた

`git archive HEAD` で**追跡されているファイルだけの木**を作り、`node_modules` だけ
symlink して画面側と functions 側の試験を走らせた。どちらも通る。

## 確かめていないこと

決済画面や管理画面を開いて券を選んではいない。
