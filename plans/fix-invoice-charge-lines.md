# 税率区分の外にある金額を明細に出す（表示のみ）

omochikaeri-docs#180

## 何を直すか

レシートと PDF の税率区分は**商品の小計しか含んでいない**のに、印字される合計には配達料金・
心づけ・EC 送料・割引が乗る。PR #1813 で登録番号を印字するようになったので、この書類は
適格簡易請求書を名乗るが、**区分の合計が自分の合計と合わない**。

さらに **EC 送料と割引はどちらの書類にも行が無い**。`totalCharge` だけが動き、明細から差額の
出どころが読めない。

## 表示だけ直す（税額には触れない）

調べた結果、これは表示の問題ではなく**そもそも課税されていない**:

- `orderAccounting()` は `food_sub_total` と `alcohol_sub_total` だけで税を出す
- 配達料金は `orderAccounting()` の後に計算される
- `totalCharge = order.total + roundedTip + shippingCost + deliveryFee - discountPrice`
- 割引は `totalCharge` から引かれるだけで `tax` に影響しない

正しく課税すると**外税の店舗では顧客の請求額が上がる**（Stripe の決済金額も変わる）。
配達料金が 10% か 8% か、心づけが不課税かサービス料として課税か、割引を各区分にどう按分するか
を決めないと書けない。決めずに書くと金額が法的に間違った書類になり、現状より悪い。

よってこの変更は**記載だけ**。請求額も税額も変えない。正しい課税は #180 に残す。

## やること

- いま行が無い **EC 送料と割引を明細に出す**。0 のときは出さない
- 配達料金と心づけは触らない。0 でも出ている現状を変えると、ほぼ全てのレシートの見た目が変わる
- どちらの金額かは `kind` で決まる（値では見分けない）。判断は共有関数 `extraCharges` に置き、
  レシートと PDF が食い違わないようにする
- PDF の新しい行に「税込」とは書かない。これらに消費税は計算されていない
  （既存の `心づけ(税込)` / `配送料(税込)` は触らない — 別の判断が要る）

## 確認

- 旧実装と並走させ、**送料も割引も持たない注文で全文が一致する**ことを確認する
- 変異: 0 を出す / 数値判定を緩める / 行の追加を消す
