# 売上報告の一行を組み立てる関数に試験を足す

## なぜ

`order2ReportData`（`src/models/orderInfo.ts`）は、売上報告と書き出しの一行分を作る。
店舗が売上を数え、税を申告するのに使う数字がここで決まる。試験が無かった。

Firebase も vue も要らない純粋な関数なので、そのまま呼べる。実装には触れていない。

## 留めたもの

- **心づけにかかる税** — 心づけは税込で受け取るので、そこから税の分を割り出す
  （上に乗せるのではない）。丸め、0円のとき、率を渡さないとき
- **区分を持たない古い注文** — 全額を食品として扱い、酒は0にする。持たないまま出すと
  税率ごとの内訳が報告から消える
- **受渡方法**が行に載ること
- **日時**が Date に直ること、確定時刻を持たない注文でも落ちないこと
- **引数をその場で書き換えること**。返り値は渡した実体そのもの

## 留めた挙動のうち、読む人が知っておくとよいもの

**二度通せない。** 一度目で日時を Date に直すので、二度目は `toDate` が無くて落ちる。
いまの呼び出し側（`AllOrders.vue` と `ReportPage.vue`）は Firestore の snapshot から
毎回 `data()` で新しい実体を作るので起きない。同じ注文を使い回す呼び出しを足すと落ちる。

到達しないので直していない。試験で振る舞いのほうを留めてある。

## 確かめ方

`yarn test` が緑。心づけの税の向き、区分の無い注文の売上、受渡方法の3通りに崩して、
それぞれ試験が赤くなることを見た。
