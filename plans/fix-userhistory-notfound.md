# 客の注文履歴の画面が、自前で「見つかりません」の形を作っていた

## いまの形

`UserHistory.vue` の setup は、権限が無いときに `{ notFound: true }` を**その場で
組み立てて**返していた。オブジェクトのリテラルなので `notFound` の型は `true` ではなく
`boolean` に広がる。すると成功側の `notFound: false` と区別がつかず、Vue の型の
組み立てが union を絞れない。

結果、template が `v-else` の中で読んでいる `orders` や `userLog` が
「無いかもしれない」と言われていた。#1863 と同じ原因が、共有の定数を使わずに
自前で組み立てている1箇所に残っていた形。

## 変えたこと

`@/utils/utils` の `notFoundResponse` を返すようにした。あれは
`const notFoundResponse: { notFound: true }` と型が留めてあるので union が絞れる。
同じ形の他の15ファイルはもともとこちらを使っている。

## 同じ振る舞いであることの確かめ方

**読んで判断していない。** 本物の Vue（`createSSRApp` + `renderToString`）で、
自前のリテラルを返す版と共有の定数を返す版を並べ、権限がある場合と無い場合の
両方について**描き出された HTML を突き合わせた。差は出なかった。**

共有の定数を返すことになるので、**二度描いても定数が汚れないこと**も見ている。
harness は条件を変えると違う結果になることを確かめてある。
