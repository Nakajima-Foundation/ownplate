# 受取日時の計算に試験を足す

## なぜ

`src/utils/pickup.ts` の `usePickupTime` は、**客が注文を受け取れる日と時刻**を決める。
店舗ページと注文画面の受取時刻の選択肢はここから出る。出しすぎれば店が用意できない時刻の
注文が入り、出さなすぎれば受けられる注文を逃す。試験が一つも無かった。

このファイルは Firebase を読み込まない。vue の composable なので読めないと思われていたが、
最小の部品を server rendering する土台（`test/helpers/vueSetup.ts`）と pinia を使えば
**実装を一切変えずに呼べる**。

## 足したもの

- **受け取れる日数** — 今日 + 店が受ける日数。未設定のときの既定値。今日の営業が終わった後
- **受け取れる時刻** — 調理時間のぶん後ろから、刻みで切り上げ、閉店まで。明日以降は削らない
- **本日の締切** — 最後の枠、そこから調理時間を引いた注文の締切、店が早めた締切が勝つこと
- **休みの日** — 曜日で閉める、日を指定して閉める
- **受け取れない時間帯** — 店舗ごとの穴、曜日ごとの穴
- **商品ごとの制限** — 商品の休業日と時間帯、片側だけの設定は無視されること

時刻は**今日の0時からの分数**で組み立てている。`midNight()` がローカルの0時を返すので、
絶対時刻で書くと日本と UTC の CI で答えが変わる。

## ひとつだけ実装を直した（型のみ）

`businessDay` の宣言が `{ [key: string]: string[] }` だったが、**実態は真偽値**。
リポジトリ自身の `defaultShopInfo` が `{1: true, ...}` を入れていて、読む側は全部
真偽として扱っている。`boolean` に直した。

型だけの変更なので実行される JavaScript は変わらない。確かめたこと:

- `tsc --noEmit`（本体・試験の両方）、`yarn build`、`yarn lint` が通る
- **`vue-tsc` の指摘件数が前後で変わらない**。`businessDay` 由来の指摘は前後どちらにも無い
- #1856 の試験で、型に合わせて `["open"]` と書いていた箇所を真偽値に直せた

## 確かめ方

`yarn test` と `cd functions && yarn ci_test` が緑。受取日数・調理時間の既定値・刻み・
切り上げの境目・臨時休業・Timestamp の変換・休業日・受け取れない時間帯・商品ごとの休業日の
9通りに崩して、すべて赤くなることを見た。

`git archive HEAD` で追跡分だけの木を作っても通る。

## 確かめていないこと

注文画面を開いて受取時刻を選んではいない。
