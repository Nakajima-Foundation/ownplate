# ダイアログの表示中しか読まない値に `?.` を足す

## いまの形

`DialogBox.vue` は `dialogStore.dialog?.alert` と `?.error` を computed で持つ。
`dialog` は **何も出ていないとき `null`** で、それが通常の状態。つまり
`alert.value` / `error.value` が undefined になるのは型の嘘ではなく本当のこと。

読む側（template）は `<div v-if="error">` と `<div v-if="alert">` の中でしか読まない。
その守りをスクリプト側の型は見られないので、`error.value.message` などが
「無いかもしれない」と言われる。

## 大元から `?` を外せない理由

`dialog` を非 null にはできない（`resetDialog` が `null` を入れるし、初期値も `null`）。
ここは省略可が正しいので、読む側で受けるしかない。

## `?.` にした理由

**値が有るときは `?.` は何もしない。** 影響するのは、いま例外になっている経路だけで、
そこが例外でなくなる。有る／無いの判断も、Sentry へ送る位置も変えていない。

早期returnで「無いときは即 return」にすると `Sentry.captureException` を通らなくなる。
そこは変えたくないので、`?.` を選んだ。

| | 前 | 後 |
|---|---|---|
| `error` が有る | 変わらない | 変わらない |
| `alert` が有る | 変わらない | 変わらない |
| `error` が無いのに文面を読む | Sentry へ送ってから例外 | Sentry へ送って `""` を返す |
| `alert` が無いのに「はい」 | 例外（閉じない） | 何もしない（閉じない） |

下2行は template の `v-if` の外なので、いまの画面からはたどり着かない。
たどり着けたとしても例外が消える方向で、閉じる／閉じないは変わらない。

## 確かめたこと

`setAlert` の呼び手17箇所すべてが `callback` と `code` を渡していること、
`dialog` へ書き込む経路が store の4つの関数だけであること、`src/` に js が
残っていないことを数えた。`DialogAlertData` の宣言は実装と合っている。

## 確かめていないこと

画面を開いてダイアログを出していない。
