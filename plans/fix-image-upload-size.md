# 5MB を超える画像を、送る前に弾いて理由を出す

omochikaeri-docs#169

## 何が起きているか

店舗オーナーが 5MB を超える画像を選んで保存すると、ポップアップに
「飲食店情報の保存に失敗しました」としか出ない。**画像が原因だと分からない。**

真因は Storage のルール（`storage.rules` の `isImageWithinLimit`）が 5MB を超える書き込みを
403 で拒むのに、フロントに事前の検査が無く、`saveRestaurant` の catch が汎用のエラーを出すだけ
だったこと。

## 直し方

issue の対策案のうち **(b) 送る前に検査して理由を出す**。(a) のクライアント側リサイズは
画質の判断が要るので別途。

判定は `src/utils/imageUpload.ts` に純関数として置く。`ImageUpload.vue` は pdfmake 同様
単体テストから読めないので、判定をあちらに置くと検証できない。

- 画像でない / 5MB 超 の場合は**親にファイルを渡さない**。渡すと保存時に 403 になる
- 入力欄の下に理由を出す。文言は全9言語に入れる
- 種別も見る。入力欄の `accept` は画像しか選ばせないが、**ドラッグ＆ドロップはそれを通らない**

アップロード経路は3つ（店舗の profile / cover、商品画像）だが、**すべて `ImageUpload.vue` を
通る**ので1箇所で足りる。

## 上限はルールと突き合わせる

定数を基準に書いたテストは定数と一緒に動くので、上限を変えても赤くならない
（実際そうなっていた）。合わせるべき相手は `storage.rules` なので、テストがルールを読んで
突き合わせる。画面だけ・ルールだけ・比較演算子だけ が変わっても赤くなる。

## 確認

- 変異: 大きさを見ない / 境界を `>=` に / 種別を見ない / 画面だけ上限変更 / ルールだけ上限変更 /
  ルールの比較演算子を変更
- `yarn lint` / `yarn test` / `yarn typecheck:test` / `yarn build`
- Vue の挙動を実測: `style` は prop として捕まり fallthrough しないので、ラッパーを足しても
  ボックスの大きさは保たれる

## やらないこと

- クライアント側のリサイズ（対策案 a）
- `storage.rules` の git 管理（対策案 c）。**すでに PR #1733 で入っており、issue の記述は古い**
- 画像以外の理由で保存が 403 になる場合（サブアカウントの権限など）は、いまも汎用のエラーのまま
