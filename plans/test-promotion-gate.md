# 割引が使えるかどうかの判定に試験を足す

## なぜ

`getPromotion`（`functions/src/functions/order/promotion.ts`）は、券が使えるかを決める関門。
ここを抜けた注文は請求額が下がる。緩めると、終わった催しの券や条件を満たさない注文にも
割引が乗る。

試験は `getDiscountPrice`（いくら引くか）だけにあり、**使えるかどうか**の判定には
無かった。

Firestore からは券の中身を読むだけなので、作り物の transaction を渡せば判定そのものを
試験できる。実装には触れていない。

## 留めたもの

- **止めた券・無い券**を通さないこと
- **しきい値ちょうど**は通り、一円足りなければ通らないこと
- **催しの期間** — 期間を持たない券は日付を見ないこと、始まる前と終わったあとを
  弾くこと、片側だけ決めた催しはその側だけ見ること
- **支払い方法の縛り** — カード専用の券を現地払いで通さないこと、その逆も
- **使用履歴の置き場**が客ごとに分かれていること

## 確かめ方

`cd functions && yarn ci_test` が緑。判定の比較を4通りに崩して、それぞれ試験が赤くなる
ことを見た（しきい値の向き、期間の向き、支払い方法の縛りの向き、止めた券の見落とし）。
