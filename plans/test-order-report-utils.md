# 注文の集計と書き出しに試験を足す

omochikaeri-docs#196 の続き。

## 何をするか

`src/utils/csv.ts` と `src/utils/dateUtils.ts` に試験が無い。どちらも店主が売上を数えるときに通る。
**実装には触らない。**

## 留める規則

- **先頭の BOM**。無いと Excel が UTF-8 と認識せず日本語が化ける
- **区切り記号は囲むのではなく空白に置き換える**。値の中のカンマや改行で列がずれない
- **合計行の範囲は注文の数に合わせて伸びる**（`data.length + 1`）
- **合計行の列記号は A-Z しか作れない**。27列目以降に式を付けると `AA` ではなく `[` を指す。
  いまの見出しでは式の付く列（`count` / `total`）が内側に収まっているので到達しない。
  収まっていることを検査で留め、検査が空振りしないことも別に確かめる
- 月は0始まりなので `+1`。ゼロ詰めを落とすと文字列の並び順が崩れる
- 深夜への寄せ。時刻が残ると、その日の早い注文が集計から落ちる
- **月次は1日へ寄せてから月を動かす**。逆にすると、月末に実行したとき31日の無い月を飛び越す

## 確かめ方

規則ごとに実装を壊して赤くなることを確かめ、復元を md5 で照合する。

「1日へ寄せてから月を動かす」だけは、実行した日が移動先の月に存在しない日（29〜31日）でないと
差が出ない。試験は規則を見ているが、常に捕まえるには `midNightOfMonth` が現在時刻を引数で
受け取る必要がある。今回は実装に触れないので、そのことを注釈に残すに留める。

## やらないこと

`src/utils/reportUtils.ts` は見出しの並びを定義した配列だけなので、試験は配列を書き写すだけになる。
列記号の上限の検査からは参照するが、それ自体の試験は足さない。
