# 試験の穴を総当たりで探し、試験できる関数に片端から試験を足す

## 1. 総当たりで穴を探す

試験が読んでいる `src/` のファイルに、機械的にコードを壊して回った。比較の向きを変える、
`&&` と `||` を入れ替える、`??` を `||` にする、真偽値を反転する、数値を一つずらす。
壊したのに `yarn test` が緑のままなら、そこは試験が見ていない。

壊す・走らせる・戻すの道具は使い捨て。残るのは、見つけた穴を埋めた試験のほう。

留めたのは、値が間違っていたら客か店舗に見える形で出るものだけ。

- `imageUtils`（`RestaurantUtils.ts`）— 拡大表示の開閉。試験が無かった
- `getEditShopInfo`（`admin/shopInfoPayload.ts`）— 営業時間の並べ替えと、未設定の項目を
  空の値に置き換えるところ
- `buildOrderDocDefinition`（`lib/pdf/orderDocDefinition.ts`）— 明細1行の金額、
  選んだオプションの行、心づけ、配送料、区分の無い注文の税額
- `pdfStyles.ts` — レシートの紙の幅と余白
- `MAX_DEVICE_NAME_LENGTH`（`pushFormat.ts`）— 画面側の上限と、`functions/` 側が実際に
  詰める長さが一致していること

### 埋めずに残したもの

- **体裁の値**（文字の大きさ、余白、太字、罫線）。「間違い」が定義できない。紙の幅だけは
  はみ出す／余りすぎるが起きるので留めた
- **比べる関数の返り値**（`a > b ? 1 : -1`）。正なら何でも、負なら何でも同じに動く。
  等しいときの向きだけが変わるが、それを留めると処理系の並べ替えの実装を留めることになる
- **`??` を `||` に変えたもの**（`pushFormat.ts`）。既定値が偽値と同じか、値が配列か
  オブジェクトなので、どちらでも同じに動く
- **営業時間の未入力の枠を落とすところ**（`shopInfoPayload.ts`）。型が認めない形なので
  渡せない。SingularitySociety/omochikaeri-docs#208

## 2. 試験できる関数に片端から足す

`utils.ts` の関数は「vue の composable だから試験できない」と思われていたが、
最小の component を一度だけ server rendering すれば setup が走るので、`useI18n` も
`useRoute` も使える。実装には触れていない。下ごしらえは `test/helpers/vueSetup.ts`。

i18n は画面が使うものをそのまま読み込む。試験用に組み直すと、文言や通貨の設定が
実物と違っていても気づけない。

足した先:

- **時刻の表示** — 営業時間の分数を文字にする3つ。日本語と英語で12時台の扱いが違う
- **経路の組み立て** — LINE の中かどうかで全リンクに前置きが付く。店舗 id の取り出し、
  共有リンク、上位管理者の画面かどうか
- **注文明細の組み立て**（`getOrderItems`）— 行の分かれ方、注文時の写しと今のメニューの
  どちらから取るか、写真だけは今のメニューから取ること
- **受渡方法**、**提携先の引き当て**、**開閉の状態**、**オプションの表示**
- **電話番号の国内表記** — 直せなかったときの振る舞いが2つの関数で違う
- **看板の画像の言語切り替え**
- **売上表と書き出しの列** — 見出しの文言が揃っていること、送り先つきが通常の上位集合であること
- **オプションの差額** — 全角の符号（日本語の入力で出やすい）

### 足せなかったもの

`promotion.ts` と `admin/RestaurantPageUtils.ts` と `admin/Toggle.ts` は、純粋な関数が
Firebase を読み込むファイルに同居していて、読み込んだ時点で初期化が走るため試験から
呼べない。#197 と同じかたち。

注文の数とオプションが配列でない古い形は、型が認めていないので渡せない。
SingularitySociety/omochikaeri-docs#209

## 確かめ方

`yarn test` が緑。埋めた穴については、同じ総当たりをもう一度掛けて、対象の変異が
赤くなることを見た。
