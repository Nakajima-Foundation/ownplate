# fix: 送料の計算（costCal）で 0 円以上の無料が効かない／一覧の外で NaN が返る

omochikaeri-docs#207。

## 1. 無料になる金額が 0 だと課金される

`freeThreshold || null` で 0 が「設定なし」になり、管理画面の読み込み（`Postage.vue` の
`if (data.freeThreshold)`）でも 0 が落ちて「OFF」と表示される。

- 読み方を `freeThresholdOf` にまとめ、`costCal` と `Postage.vue` の両方で使う
  - 数はそのまま（0 を含む）。`NaN` は設定なし
  - 空でない文字列は `Number()`。数にならなければ設定なし
  - それ以外（`undefined` / `null` / `""` / 真偽値など）は設定なし
- `""` を設定なしにするのは、管理画面の数値欄を空のまま保存すると `""` が入るため。
  `?? null` だけにすると `total >= ""` が常に真になり、常に無料になってしまう
- `PostageInfo.freeThreshold` の型を実態（`number | string | null`）に合わせる

## 2. 一覧の外を指すと NaN が返る

範囲外の都道府県や一覧の壊れた値は `Number(...)` が `NaN` になり、注文の合計と決済に流れる。
`NaN` のときは 0 を返す。

## 変わる挙動（旧コードと生成入力で突き合わせて確認）

- 無料になる金額が数の 0 → 課金されていたのが常に無料に（意図どおり）
- 送料が数にならない場合 → `NaN` だったのが 0 に
- 無料になる金額が真偽値（管理画面からは入らない壊れたデータ）→ 設定なしとして扱う

それ以外の入力では旧コードと同じ結果になる。

## 影響

- `commonUtils.ts` は functions へコピーされ、注文確定（`orderPlace.ts`）と注文変更（`orderChange.ts`）の
  送料計算に使われる。画面とサーバで同じ関数なので、表示と請求はずれない
- 既存の店舗で `freeThreshold: 0` が保存されているものは、デプロイ後に送料が常に無料になる
