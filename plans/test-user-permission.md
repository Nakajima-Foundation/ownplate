# 画面側の身元判定に試験を足す

## なぜ

`src/store/user.ts` と `useAdminUids`（`src/utils/utils.ts`）は、画面側の身元と役割の判定。
**メールが入っていれば店舗の管理者、電話番号が入っていれば注文者**として扱い、役割は
Custom Claims で付く。試験が無かった。

サーバ側の同じ判定には試験を足してある（`functions/tests/unit/auth_test.ts`）。
こちらはその対。

## 留めたもの

- **メールと電話番号で種別を分けていること。** どちらも持たない利用者はどちらでもない
- **署名前（undefined）と署名して誰でもない（null）を、どちらも「まだ誰でもない」
  として扱うこと**
- **Claims が届いていないあいだは役割を持たない側**に倒れること。
  上位管理者とオペレーターが別であること
- **サブアカウントは自分の uid で署名するが、店舗のデータは親の uid の下**にあること。
  サーバ側の `validate_owner_admin_auth` と対になる
- **署名し直したときに前の利用者の値が残らないこと。** 残ると切り替えたあとも
  前の店舗を読む

`Claims` は store から export されていないので、受け取る側の型から導いている。
書き写すと store が項目を増やしたときに気づけない。

## 確かめ方

`yarn test` が緑、`npx tsc --noEmit -p tsconfig.test.json` が通る。
管理者の uid の出し方、サブアカウントの見分け、親の uid、LINE の利用者の4通りに崩して、
それぞれ試験が赤くなることを見た。実装には触れていない。
