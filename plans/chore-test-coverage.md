# 単体試験のカバレッジを CI で見えるようにする

omochikaeri-docs#201

## やること

`test:coverage` を足し、CI の `build-vue` で `yarn run test` の代わりに走らせる
（試験も同時に走るので二度手間にならない）。

除外は `src/lang/**`（翻訳の辞書。ただのデータで、混ざると全体が100%側へ引っ張られる）と
`test/**`。

## この数字が言っていないこと

**読み込まれたファイルだけを数える。** 試験の無いファイルは報告に現れない。だから
「src の何割が覆われているか」ではなく「**試験が読んだファイルのうち何割の行が走ったか**」。

そのせいで、**新しいモジュールに試験を書き始めると数字が下がる**。実際そうなった —
カート金額の試験が `utils.ts` を読むようになり、その未試験部分（関数 39.76%）が平均に入った。
下限をきつくすると、試験を増やす動機を罰することになる。

## 下限が何を捕まえるか（測った）

| やったこと | 結果 |
| --- | --- |
| 覆われているファイルに試験の無い関数を3つ足す | **素通り** |
| 試験を2ファイル外す | **素通り** |
| 試験を半分外す | **落ちる** |

**崩壊は捕まえるが、じわじわの劣化は捕まえない。** 下限はそのつもりで置いてある
（いまの測定値よりかなり下）。ratchet ではなく火災報知器。

数字は `package.json` の script に書いてある。prose ではなく実行されるものなので、古くならない。

## やらないこと

「この一覧のファイルは試験から読まれていること」という別の検査は足さない。
そちらのほうが「試験ファイルが消えた」を捕まえられるが、一覧の維持費がかかる。
下限で足りなければあとで足す。
