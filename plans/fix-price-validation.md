# 商品の値段を数に縛る（omochikaeri-docs#228）

## いま起きていること（測ったこと）

- `firestore.rules` の `menus/{menuId}` は「誰が書けるか」だけを見ている。`price` に
  文字列を PATCH しても 200 で通る
- 文字列の値段はお客様の画面に `0 (inc. tax)` として出て、その品物で**注文確認まで進む**
- 画面（`MenuItemPage.vue`）の検査は**空かどうかだけ**。`1.5` や `-100` は知らせが出ず、
  `getNewItemData` の `Math.round(Number(...))` が黙って `2` や `-100` にして保存する

## 直す範囲

1. **規則** — `menus/{menuId}` の write に `request.resource.data.price is number` を足す。
   範囲は見ない（数であることだけ）
2. **画面** — 空に加えて「数であること・0 以上・整数」を見る。黙って丸めない

規則が守りで、画面は使い勝手。**画面だけでは守りにならない**（REST から直に書ける）。

## やらないこと

- 上限の検査（規則側）。いまの入力欄に `max` はあるが、規則では見ない
- 商品の保存を callable に寄せること。書き込み経路の作り替えになるので別の話

## 確かめ方

- 規則: 文字列の `price` を PATCH して**弾かれる**こと（いまは 200）
- 画面: `1.5` と `-100` で知らせが出て、保存の口が死ぬこと
- 既存の e2e 一式が通ること（商品の保存経路に触るため）
